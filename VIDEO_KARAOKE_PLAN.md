## 1. Цель и ожидаемое поведение

Пользователь загружает видео с песней. Приложение извлекает звук, отделяет
вокал, распознаёт текст и накладывает караоке на исходное движущееся видео.
В итоговом MP4 звучит подготовленная минусовка с выбранной долей вокала.
Длительность результата ограничена длительностью подготовленной аудиодорожки.
Повторная сборка сохраняет выбранное видео, текст и интервалы вокала/эффектов
и не запускает нейросети повторно.

Приоритеты:

1. P0: остановить бесконечный рендер и выбор неправильного звука.
2. P1: сделать загрузку, сохранение и пересборку видеопроекта надёжными.
3. P1: корректно завершать отмену/ошибку без повреждения готового результата.
4. P2: проверить размеры, интерфейс, форматы и документировать ограничения.

## 2. Как устроен проект

- Python 3.11, зависимости через uv; Gradio с JavaScript-таймлайном.
- `downloader.py` принимает файлы/URL. Из локального видео извлекается WAV
  PCM 16 bit, 44.1 кГц, stereo; путь к оригинальному видео возвращается отдельно.
- `cli.py:analyze_and_transcribe` запускает Demucs, Whisper, выравнивание,
  готовит waveform/FX и сохраняет JSON состояния.
- `aligner.py` отвечает за тайминги слов, русские строки и формат редактора.
- `mixer.py` собирает минусовку с автоматизацией вокала.
- `ass_writer.py` создаёт ASS с подсветкой и эффектами; `emoji_layer.py`
  готовит PNG/ffconcat для цветных emoji.
- `cli.py:render_from_state` собирает звук, субтитры и запускает `video.py`.
- `video.py` читает оригинальное видео непосредственно в FFmpeg, масштабирует
  до 1920×1080, обрезает края, приводит к 30 fps и прожигает ASS.
- `app_ui.py` содержит загрузку, настройки, сохранение/открытие проектов,
  первоначальную генерацию и пересборку.
- `cancel_manager.py` регистрирует дочерние процессы и позволяет их остановить.
- В `tests/test_karaoke.py` есть проверки извлечения звука из видео и
  рендера на изображении, но нет регрессии для фонового видео со своей
  аудиодорожкой, ограничения длительности и правильного выбора звука.

## 3. Подтверждённая причина роста файла

В `video.py:render_karaoke_video` видеофайл подаётся как input 0 с
`-stream_loop -1`, подготовленная минусовка — как input 1.

В ветке с emoji есть явные `-map [outv] -map 1:a`. В обычной ветке есть
только `-vf`, выбор потоков оставлен FFmpeg. Если у исходного видео есть
аудиодорожка, FFmpeg может выбрать её вместо минусовки. На синтетическом
клипе с одинаковым количеством аудиоканалов он выбрал именно input 0.

Получаются два бесконечных выходных потока из зацикленного видео: картинка
и исходный звук. Короткая минусовка не попала в выход, поэтому `-shortest`
не завершает кодирование. Одновременно теряется эффект удаления вокала.

### Проведённый эксперимент

Системный FFmpeg, временные синтетические файлы: исходный клип 1 секунда,
320×180, 10 fps, звук 440 Гц; отдельная аудиодорожка 2 секунды, 880 Гц.
Проверялась схема входов и выбора потоков, без нейросетей и прожига ASS.
Зависший процесс принудительно завершался через 4 секунды; временные файлы удалены.

| Схема | Выбранный звук | Результат |
| --- | --- | --- |
| Без явного map, как в обычной ветке | `0:1`, звук зацикленного видео | Не завершилась; длительность 700.882449 с, размер 6 292 165 байт |
| `-map 0:v:0 -map 1:a:0` | `1:0`, отдельный WAV | Завершилась; длительность 2 с, размер 20 523 байта |

Это воспроизводимый механизм неограниченного роста. Конкретный сообщённый
пользователем файл >10 ГБ пока не идентифицирован: на момент проверки весь
`output` занимал около 2.3 ГБ, файлов >100 МиБ там не было. Не утверждать,
что найден именно тот промежуточный файл. Проверить также выдачу Gradio
и его временный каталог при воспроизведении пользовательского сценария.
В текущем `video.py` отдельный промежуточный видеофайл не создаётся:
FFmpeg пишет сразу конечный MP4.

## 4. Другие обнаруженные проблемы

1. Первичная генерация из отдельного поля загрузки видео принудительно включает
   видеофон только в локальной переменной. Галочка интерфейса относится к
   YouTube и по умолчанию выключена. Пересборка использует её текущее значение,
   поэтому загруженный клип может замениться обложкой/статичным фоном.
2. `video_bg` хранит путь к загрузке Gradio, который может исчезнуть после
   очистки временных файлов. Простое сохранение этого пути не делает проект переносимым.
3. Расширения проверяются разными списками: `.m4v` распознаётся загрузчиком,
   но отсутствует в определении видеофона в `video.py`.
4. Извлечение WAV и обложки в загрузчике использует обычный `subprocess.run`;
   отмена не управляет этими процессами через реестр.
5. Нет явного предела времени выходного медиа; корректность зависит от
   выбора потоков и `-shortest`, в том числе при бесконечных PNG-входах emoji.
6. Рендер пишет поверх готового MP4. Ошибка или отмена могут оставить
   частичный файл и уничтожить предыдущую удачную сборку.
7. Качество и битрейт уже ограничиваются пресетами. Просто уменьшать битрейт
   недостаточно: бесконечная длительность остаётся бесконечной.

## 6. Проверки и критерии приёмки

1. Клип со звуком + минусовка: результат конечный; слышен выбранный mix.
2. Клип без звука как фон + отдельный WAV: успешный рендер.
3. Видеоисточник песни без аудио: понятная ошибка до Demucs/Whisper.
4. Исходник короче/длиннее WAV: результат соответствует WAV, без вечного loop.
5. Варианты без emoji, с emoji в словах, с частицами и с их комбинацией:
   одинаковые правила звука и завершения.
6. Проверить light/balanced/hq, VideoToolbox и software fallback на macOS.
7. Для коротких синтетических фикстур допустимое отклонение длительности
   до 0.15 с (кадры/округление AAC), ровно одна видео- и одна аудиодорожка.
8. Проверить, что картинка движется и ASS виден поверх неё: сравнить кадры
   до/во время строки и кадры разных моментов. Вручную проверить синхронизацию.
9. Оценка размера по битрейту: `секунды × (видео + аудио) / 8`.
   Для balanced и 5 минут ориентир около 167 МБ при 4.2+0.256 Мбит/с;
   верхний бюджет регрессии учитывать maxrate 6.5 Мбит/с, AAC и контейнер.
   Для software CRF это ориентир/верхний бюджет, не обещание точного размера.
10. Во время рендера нет отдельного гигантского промежуточного видео;
    пиковый объём учитывать отдельно от готового результата, исходника,
    WAV/stems и кеша загрузки. Проверить повторную сборку минимум три раза.
11. Отмена и искусственная ошибка сохраняют предыдущий MP4, завершают
    процессы и убирают только временный результат данного запуска.
12. После открытия проекта и редактирования текста фон остаётся видео,
    интервалы вокала/FX сохраняются, нейросети не перезапускаются.
13. Обычный сценарий аудио + картинка и существующие регрессии продолжают работать.

Порядок запуска: новые сфокусированные тесты → существующие тесты видео,
emoji и состояния → полный набор → ручная проверка UI и короткого MP4.
Синтетические проверки не требуют скачивания весов нейросетей и YouTube.

Команды из корня проекта:

```sh
uv run --with pytest python -m pytest tests/test_karaoke.py
uv run karaoke-ui
uv run python -m karaoke.cli --help
```
